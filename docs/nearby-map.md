# Homepage area map

`NearbyMap.svelte` provides the village/region switch, category selector, walking/driving modes and selected road route. The section sits after the final booking invitation and before the footer. Its open list/map layout spans the full page width with responsive side padding; the destination list keeps a readable width while the map fills the remaining space. Copy is in `src/lib/data/nearby-copy.ts` (DE/EN).

The activated map supports mouse-wheel zoom. Destination changes and the reset control animate to the route bounds; the route fades in and the selected marker briefly highlights. Reduced-motion preferences disable these effects. Names appear beside markers when space permits, prioritizing the selected destination and guesthouse; label collisions are recalculated after panning, zooming and resizing. Hover/focus tooltips include the full name, travel mode, approximate duration and distance. Numbers remain as a secondary reference to the destination list.

## Data and maintenance

- `src/lib/data/nearby-places.json`: 14 curated destinations (six local, eight regional), public coordinates, localized descriptions, original OSM object references and individual information sources. Coordinates checked on 2026-10-10 using the OSM map API for Weißbriach and Nominatim for regional targets. The pool target is beside the pool restaurant; the local winter target is the Hammerboden base station. Nassfeld means the Millennium Express valley station, not the mountain. Weissensee means the Techendorf boat landing; Pressegger See means Strandbad Oswald / Seehexe on the southern shore.
- `experienceIds` links all 13 seasonal entries from `experience.ts` to one map destination each. Shared starting points stay on one marker: Hammerboden covers skiing, access to the Nadaln trail and Berggeist sledding; Millennium Express covers summer lifts and winter skiing. The summary links directly to the localized seasonal experience page and anchor. The longer regional list scrolls within the sidebar.
- New regional access points: Klammwirt at the Garnitzenklamm entrance (OSM way 89231837), Radnig natural pool for Golz (node 881038463), Reißkofelbad for Reißkofel/Jochalm (node 240068541), Hermagor station for the R3 cycle path (way 29947448), Nassfeld Pass for snowshoeing (node 1626728615). The `source` on each destination documents the provider's access instructions; `additionalSources` records supporting winter maps. Times cover the approach only, not hiking, skiing, cycling, lift rides or ice access. Existing Reißkofel/Radniger-Alm and Weißbriach/Nassfeld mismatches in the experience copy were corrected. Variable festivals and generic quick ideas have no invented fixed markers.
- Guesthouse origin matches `guesthouseFacts.geo`. A regression test prevents the two datasets drifting apart.
- `src/lib/data/nearby-routes.json`: recorded FOSSGIS/OSRM road/path geometries, meters, seconds, endpoint snapping distance and generation date. Coordinates are GeoJSON longitude/latitude pairs. These OSM-derived geographic datasets are provided under [ODbL](https://www.openstreetmap.org/copyright), with attribution in the interface. The small JSON sources remain available in the repository alongside the application.
- Refresh explicitly with `node scripts/update-nearby-routes.mjs` after verifying destination changes. This makes two sequential requests per destination (currently 28), with a 1.2-second gap; it does not run during a build or in a visitor's browser. A failed request leaves the previous dataset intact. Review endpoint snapping and run `node --test tests/nearby.test.cjs` after refreshing.
- Recheck destinations and routes before seasonal content updates. Route estimates do not account for traffic, parking, closures, snow, personal walking pace or opening hours. They are orientation aids, not live navigation. Routing can stop at the nearest accessible road/path; the interface discloses the possible last short walk. External Google directions use the same origin, destination and mode, but may calculate a different current route.

## Loading and providers

Leaflet and its CSS load dynamically only after “Karte laden” / “Load map”. The tile layer uses `https://tile.openstreetmap.org/{z}/{x}/{y}.png`, with visible attribution, normal browser caching and Referer behavior, no prefetch or offline downloads. Follow the [OSM tile policy](https://operations.osmfoundation.org/policies/tiles/); this public service has no availability guarantee. A tile error leaves the curated list, cached metrics and directions links usable. A larger site should use a contracted tile provider if traffic or availability needs warrant it.

The app never requests device geolocation. Activation is local to the mounted component; closing the map removes it and cancels further map interaction. No persistent consent setting is written. Tile requests disclose ordinary request data to OSMF after activation, explained at the point of loading and in the privacy page. [OSMF privacy policy](https://osmfoundation.org/wiki/Privacy_Policy). The public routing service is accessed only by the maintenance script; [FOSSGIS service terms](https://routing.openstreetmap.de/about.html) require attribution and at most one request per second.

Basic category/filter/route geometry/link tests are in `tests/nearby.test.cjs`. Full responsive and accessibility review remains in `design-qa.md` per the user's deferred QA scope.
